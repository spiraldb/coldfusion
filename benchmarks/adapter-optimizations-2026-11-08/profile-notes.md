# Profiles explaining rejected experiments

The Vortex Q21 view-array recording spent 49.39% of sampled self CPU dropping Arrow buffer descriptors, 34.76% in StringView take operations, and 12.76% allocating memory: 96.91% combined. Hash-join build collection accounted for 99.61% inclusive CPU. The matched canonical recording did not have this view-handling hotspot. This identifies a concrete cost in that Vortex execution; it does not prove the cause of every Parquet tail. Full-suite means, including repeated Q21 stalls, rejected views for both Parquet codecs and Vortex.

In Zstd Parquet Q6 with metadata caching off, ParquetMetaDataReader::load_and_finish accounted for 0.1975% inclusive CPU. A Zstd sequence-decoding symbol accounted for 44.74% self CPU and the main Huffman decoding symbol for 2.53% self CPU. The nested load_metadata frame has the same 0.1975% inclusive share; adding the two would double-count. Metadata parsing was a small CPU target in this recording. The separate full-suite cache experiment reduced throughput by about 0.70% for Zstd and 1.37% for LZ4_RAW, so the cache was removed. This warm local Q6 profile does not measure remote metadata I/O or establish a universal bound on caching benefits.

The broad static filter also regressed full-suite means. Its ending Arbor controls drifted, so precise cross-engine rankings remain uncertain; adjacent and reversed comparisons agreed on rejection. Staged split-conjunct filtering had a small Zstd gain and larger LZ4_RAW loss in a four-query screen, which did not justify retaining it.

All recordings used Samply launch mode and a 15-second window. Cropping excluded setup and CPU deltas crossing runner_ready, but retained warmups and validation. Vortex Q21 completed three timed executions with views and thirty canonical executions; Q6 completed 400 timed executions with two warmups per mode. Both matched pairs used the same binary within their pair and validated exact results. The profile windows cover only the beginning of those runs. Multi-thread CPU totals are not normalized per-query costs, and profiler timings are diagnostic rather than throughput measurements. Self and inclusive percentages must not be added.

The JSON retains exact binary/profile/symbol hashes and selected public function names. It contains no SQL, local paths, private code, or patch bodies. All measured profile binaries are explicitly experimental; final committed cohort validation remains separate.
